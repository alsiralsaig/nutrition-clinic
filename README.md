# 🥗 نظام إدارة عيادة التغذية — Nutrition Clinic

تطبيق ويب كامل (خادم + قاعدة بيانات + واجهة عربية RTL) لتنظيم عمل عيادة تغذية:
ملفات المرضى، الزيارات والقياسات، البرامج الغذائية، المواعيد، المدفوعات، التقارير، الحماية، والنسخ الاحتياطي —
**ومبني بحيث يُربط لاحقاً بتطبيق Android/iPhone خاص بالمريض على نفس قاعدة البيانات.**

> لا يشبه جدول Excel: شاشات مستقلة، بطاقات مؤشرات، رسوم بيانية، محرر خطط غذائية، وأوراق طباعة A4 جاهزة.

---

## 1) التشغيل السريع

```bash
git clone https://github.com/alsiralsaig/nutrition-clinic.git
cd nutrition-clinic
npm install                 # يثبّت الخادم والواجهة معاً (npm workspaces)
npm run dev                 # يشغّل الخادم على 4000 والواجهة على 5173
```

افتح: **http://localhost:5173**

| الحساب | كلمة المرور | الصلاحية |
|---|---|---|
| `admin` | `admin123` | كل شيء: حذف، مستخدمون، إعدادات، استعادة نسخ |
| `doctor` | `doctor123` | أخصائي: إضافة وتعديل كل السجلات الطبية والمالية |
| `reception` | `reception123` | مشاهدة فقط (قراءة وتقارير وطباعة) |

⚠️ **أول خطوة بعد التشغيل:** من `الإعدادات ← المستخدمون والصلاحيات ← تغيير كلمتي السرية` غيّر كلمات المرور التجريبية.

البيانات التجريبية (14 مريضاً بزياراتهم وقياساتهم وخططهم ومدفوعاتهم) تُزرع تلقائياً عند أول تشغيل لقاعدة فارغة.
لبدء قاعدة نظيفة احذف `apps/api/.data/clinic.sqlite*` ثم أعد التشغيل (وأزل استدعاء `ensureSeed` من `server.js` إن أردت منع البذرة نهائياً).

### الوضع المُنتِج (منفذ واحد فقط)

```bash
npm run build          # يبني الواجهة في apps/web/dist
npm run start          # Express يقدّم الواجهة + الـ API على http://localhost:4000
```

ويمكن ترحيلها إلى PostgreSQL دون تغيير مسارات الـ API (انظر §7).

## 3) الوظائف المنفَّذة (مطابقة للمتطلبات)

### لوحة التحكم الرئيسية
* بطاقات: عدد المرضى، النشطون، مواعيد اليوم، إيرادات الشهر، إجمالي الإيرادات.
* إحصائيات المتابعة: من قاسوا هذا الشهر، زيارات 30 يوماً، البرامج النشطة، متوسط نزول الوزن، وتنبيه «مرضى بلا متابعة منذ 60 يوماً».
* رسوم: نمو عدد المرضى (جديد + تراكمي)، تطور متوسط الوزن/BMI/نسبة الدهون، الإيرادات الشهرية، توزيع فئات BMI، ازدحام أيام الأسبوع، جدول مواعيد اليوم بأزرار تنفيذ سريعة، وقائمة أفضل نتائج النزول.

### إدارة المرضى
* رقم ملف تلقائي `NC-0001` (قيد فريد في القاعدة — لا تكرار ولا تعديل يدوي).
* الاسم واللقب، الهاتف، تاريخ الميلاد (مع حساب العمر)، الجنس، الطول، وزن البداية، الوزن المستهدف، الهدف الغذائي، الملاحظات، حالة الملف.
* بحث فوري بالاسم أو رقم الملف أو الهاتف + فرز (الأحدث/الاسم/رقم الملف) + ترقيم صفحات + تصفية بالحالة.
* شريط بحث عام في رأس الصفحة يقترح المرضى أثناء الكتابة.

### ملف المريض في صفحة واحدة
يُحمَّل من طلب واحد `GET /api/patients/{id}/profile` ويتنقّل داخله بشريط أقسام ثابت:
**نظرة عامة** (مؤشرات + شريط «قطعته من الهدف») · **البيانات** · **القياسات** · **البرنامج الغذائي** · **الزيارات السابقة** · **المواعيد** · **المدفوعات** · **الملاحظات** (تحرير مباشر).
لكل قسم زر إضافة/تعديل مناسب، وأي موعد يُعلَّم «تمت» تُنشأ له زيارة تلقائياً.

### المتابعة والقياسات
الوزن، الطول، **BMI تلقائي**، محيط الخصر، الصدر، الورك، **نسبة الدهون**، **نسبة الخصر/الورك**، ملاحظات، وربط كل قياس بالزيارة.
رسم بيانية تفاعلية لتطور الوزن/BMI/الخصر/الدهون مع أزرار إظهار/إخفاء لكل مقياس، وجدول يعرض الفارق عن الزيارة السابقة وعن البداية.

### البرامج الغذائية
محرر بصفوف وجبات (الوجبة، التوقيت، اسم الطبق، الأصناف، الكميات، سعرات، بروتين، كربوهيدرات، دهون):
* المجاميع والإحصاء مقابل الهدف يُحسبان لحظياً، مع تلوين الانحراف عن الهدف بأكثر من 8٪.
* إضافة أصناف من جدول أغذية مبسّط يعيد حساب السعرات والماكرو تلقائياً.
* اعتماد خطة (خطة نشطة واحدة لكل مريض)، أرشفة، **نسخ خطة لمريض آخر**، تعديل، حذف.
* **طباعة / حفظ PDF**: ورقة A4 بترويسة العيادة + جدول البدائل + خانة توقيع وختم.

### المواعيد
جدول يوم مقسَّم إلى أنصاف ساعات مع إبراز الأوقات الشاغرة والحجز منها بنقرة، عرض أسبوعين مع تغيير الحالة من الجدول،
تسجيل/تعديل/حذف، نوع الزيارة، المدة، ملاحظات، **منع تداخل نفس الوقت (409)**، وملخص: مجدول/مؤكد/تمت/ملغي/لم يحضر.

### المدفوعات
المبلغ، نوع الخدمة، تاريخ الدفع، طريقة الدفع (نقدي/بطاقة/تحويل/محفظة هاتف/تقسيط)، رقم الفاتورة، موظف مُدخِل الدفعة.
حساب الإيرادات: إيراد الفترة، المتوسط، إيراد اليوم والشهر، أعلى الخدمات، التقسيم حسب الطريقة — مع **إلغاء بدل حذف** (يبقى الأثر) وحذف نهائي للمدير فقط.

### التقارير
تقرير مريض كامل · تقرير تطور الوزن · تقرير الزيارات · تقرير الإيرادات · سجل التدقيق.
لكل تقرير معاينة على الشاشة ثم **طباعة أو حفظ PDF** بورقة A4 (ترويسة العيادة، تكرار رؤوس الأعمدة، تذييل بالتوقيع).
**تصدير CSV** (بترميز UTF-8 + BOM ليعرب في Excel) للمرضى والقياسات والمدفوعات والمواعيد.

### الحماية
* شاشة دخول باسم مستخدم وكلمة مرور (bcrypt) + JWT صلاحيته 12 ساعة.
* ثلاثة أدوار: `admin` (كل شيء) · `staff` (تعديل بلا إدارة مستخدمين/حذف نهائي/استعادة) · `viewer` (قراءة فقط).
* **حماية الصيغ:** `BMI`، `BMR`/الماكرو، `waist_hip_ratio`، إجماليات البرنامج، والإيرادات — **تُحسب في الخادم فقط**؛ أي قيمة يحقنها العميل تُتجاهَل (مغطّاة باختبار).
* حقول مشتقة للقراءة فقط في الواجهة، لا يمكن لمسها.
* حماية الأرشيف الطبي: غير المدير لا يحذف ملف مريض (أرشفة بدل التدمير).
* **سجل تدقيق** لكل عملية (من، متى، ماذا، على أي سجل).
* **نسخ احتياطي**: تنزيل JSON لكل الجداول، تنزيل ملف القاعدة الخام، `VACUUM + integrity_check`، و**استعادة** مع حفظ نسخة أمان تلقائية قبل التنفيذ.
* حدّ محاولات دخول على مستوى الـ IP، و`express.json` بحد حجم، وكل الاستعلامات prepared statements (لا حقن SQL).

### التصميم
عربي RTL بالكامل، خط Tajawal/Cairo، لوحة ألوان هادئة (أخضر مائي + رملي + لمسات عنبرية)، بطاقات وظلال ناعمة،
أزرار واضحة كبيرة، تنبيهات Toast، وحالات فارغة مرشدة — بلا إحساس جداول Excel.

## 5) ربط تطبيق Android/iPhone (المرحلة القادمة)

الـ API مصمَّم ليكون مصدر الحقيقة الوحيد للويب والموبايل معاً:

1. **الدخول:** `POST /api/auth/login` → `{ token, user }`، ثم أرسل `Authorization: Bearer <token>` في كل طلب.
2. **شاشة المريض كلها من طلب واحد:** `GET /api/patients/{id}/profile` يرجّع البيانات، البرنامج الغذائي النشط،
   المواعيد، القياسات، سلسلة تطور الوزن، والمدفوعات — وهو نفس الطلب الذي تستعمله واجهة الإدارة.
3. **العقد موثّق:** `GET /openapi.json` (39 مساراً + مخططات الحقول) → ولّد منه كود الشبكة:
   ```bash
   npx @openapitools/openapi-generator-cli generate -i apps/api/openapi.json -g dart-dio -o ./mobile/api_client
   # أو: -g typescript-axios / -g kotlin / -g swift5
   ```
4. **حساب المريض:** الجدول جاهز — أضف عموداً مثل `patients.access_code` ومسار `POST /api/patient/login`
   يُصدر نفس التوكن مع حصر الوصول في `/{patient_id}/...` الخاص بالمريض، ويبقى كل شيء آخر بلا تعديل.
5. **إشعارات المتابعة:** أضف FCM/APNs، واستمع في التطبيق لتغيّر `diet_plans.status` أو اقتراب `appointments.date`.
6. **HTTPS إلزامي** في الإنتاج (reverse proxy مثل nginx/Caddy) لأن التوكن يرسل في الهيدر.

للقراءة السريعة من جهاز الموبايل التجريبي أثناء التطوير: شغّل `npm run start` وفتّح نفقاً مؤقتاً
(`ngrok http 4000` أو `cloudflared tunnel`) ثم ضع عنوانه في إعداد التطبيق.

## 6) ترحيل البيانات إلى PostgreSQL عند الحاجة

المخطط في `apps/api/src/schema.sql` قياسي؛ الفرق العملي الوحيد:

| SQLite | PostgreSQL |
|---|---|
| `INTEGER PRIMARY KEY AUTOINCREMENT` | `BIGSERIAL PRIMARY KEY` |
| `datetime('now')` | `now()` |
| `substr(x,1,7)` | `to_char(x,'YYYY-MM')` |
| `strftime('%w', date)` | `EXTRACT(ISODOW FROM date)` |
| `IFNULL` | `COALESCE` |

طبقات البيانات معزولة في `db.js` والمسارات لا تعرف SQLite إلا في الاستعلامات، فالترحيل عمل يوم واحد
(أو استبدل `better-sqlite3` بـ `pg` + مجلد `migrations/`).

## 7) النسخ الاحتياطي في التشغيل اليومي

* من `الإعدادات ← النسخ الاحتياطي`: «نسخة JSON» (كل الجداول في ملف واحد) أو «ملف القاعدة» (`.sqlite`).
* نسخة تلقائية يومية على الخادم (cron):
  ```bash
  0 3 * * * cd /srv/nutrition-clinic && node -e "const D=require('better-sqlite3');const db=new D('apps/api/.data/clinic.sqlite');db.pragma('wal_checkpoint(TRUNCATE)')" && cp apps/api/.data/clinic.sqlite /backups/clinic-$(date +\%F).sqlite
  ```
* الاستعادة من الواجهة (مدير فقط)، وتُحفظ نسخة أمان للحالة الحالية تلقائياً قبل أي استعادة.
